单人自用只需账号池 + 一个 Key。多人共享时，在此基础上加用户和策略，实现 per-user 隔离与限额。

## 三步开通团队

1. **策略**（用户页 → 策略标签）：定义并发 / RPM / 周预算 / 月预算模板。
   - 周 / 月预算**留空或填 0** 表示该周期不限制，策略列表会显示 `∞`。
2. **用户**：为成员创建账号，分配策略。
   - 管理员账号内置，不可新建。
3. **分发 Key**：每人一个 key，可选[绑定到特定账号](#per-key-绑定)。

超限请求**直接拒绝，不消耗账号资源**。

## 限额维度

| 维度 | 含义 |
|------|------|
| 并发（`max_concurrent`） | per-user 同时进行的请求数上限 |
| RPM | 每分钟请求数（滑动窗口） |
| 周预算 / 月预算 | 按 `nanousd` 精度累计的费用上限 |

## Per-Key 绑定

可以把某个 API Key 锁定到指定账号，把资源隔离开——例如给某成员固定用某个账号。绑定后，该 key 的请求只会从绑定账号中调度；绑定优先级高于[「优先消耗」](../account-pool/#优先消耗drain_first)。绑定与调度的交互细节见[账号调度器](../../dev/scheduler/)。
